# Cypher Bank ATM

Cypher Bank ATM is a local, menu-driven Java console application that simulates
basic ATM and bank-account operations. It is a learning project, not a real
banking system. It never contacts a bank or payment network.

The application provides an ATM-style console interface with progress displays
for PIN checks, cash deposits, withdrawals, transfers, receipts, and session
closing. It can also play short, locally generated confirmation/error tones.

## Requirements

- Java Development Kit (JDK) 11 or newer
- A terminal, Command Prompt, or PowerShell window

The project was most recently compiled with JDK 27.

## Start the program

Open a terminal in this folder and run:

```powershell
javac BankingSystem.java
java BankingSystem
```

To run without the ATM tones:

```powershell
java BankingSystem --silent
```

To keep the ATM colour palette but show instruction text immediately (useful on
slow remote terminals), add `--no-animation`:

```powershell
java BankingSystem --no-animation
```

If the terminal does not support ANSI colours, the program falls back to a
plain ASCII display. This avoids broken emoji or box-drawing output in older
Windows terminals and IDE consoles.

## Customer functions

After choosing **Customer login**, enter an account number and its four-digit
PIN. Three incorrect PIN attempts lock the account. An administrator can unlock
it later.

The customer menu supports:

- Balance inquiry
- Cash deposits
- Cash withdrawals
- Transfers to another active account
- A mini statement showing the latest 15 transactions
- PIN changes
- Account details

Money is stored internally as whole cents, so an amount such as `0.10` is kept
exactly rather than being affected by floating-point rounding. Amounts may have
at most two decimal places.

On a completely new installation, the program creates these demonstration
accounts:

- Account `1001` — PIN `1234`
- Account `1002` — PIN `2222`
- Account `1003` — PIN `3333`

Change these PINs before using the program for any personal demonstration data.

## Administrator setup and functions

There is no built-in administrator username or password. The first time someone
selects **Administrator login**, the program asks them to create a local
administrator username and a password of at least 12 characters. The program
then returns to the normal administrator login screen.

Administrator tools include viewing or searching accounts, viewing bank
statistics, locking/unlocking accounts, resetting a customer's four-digit PIN,
changing the administrator's own password, and deleting accounts that have an
exact zero balance. A PIN reset also restores access to a locked account.

In a real terminal, passwords and PINs are entered with terminal masking. Some
IDE consoles do not expose that facility; use a normal terminal for private
credential entry.

## Data and security

The program keeps its local data in the folder from which it is run:

- `accounts.bank` holds validated account data, transaction history, balances,
  lock status, and salted PIN hashes.
- `admin.properties` contains the administrator username and a salted PBKDF2
  password hash. It does not contain the administrator password.
- `accounts.dat.migrated.bak` is created only when an older `accounts.dat` file
  is migrated. Keep it as a recovery copy until you have verified the migrated
  data.

New account data is written to a temporary file and moved into place only after
the full write succeeds. This reduces the chance of a partially written data
file replacing good data during a power loss or crash.

PINs and administrator passwords use PBKDF2-HMAC-SHA-256 with a random salt.
They are verified against their stored hash and are not saved as readable
passwords. A previous `accounts.dat` file is imported once through a restricted
legacy reader, converted to the new format, and renamed to the backup filename
above.

## Data recovery notes

If `accounts.bank` is malformed or cannot be read, the application refuses to
replace it with default accounts. Copy the file somewhere safe before trying
recovery steps. If migration from an old installation was interrupted, check
whether `accounts.dat.migrated.bak` still exists.

Do not share `accounts.bank`, `admin.properties`, or a legacy backup. Although
credentials are hashed in the new files, those files contain private account
names, balances, and transaction history; older backups may include legacy
data that should be protected.

## Project layout

`BankingSystem.java` contains the full program: menus, account rules, secure
credential handling, persistence, ATM display sequences, and tone generation.
The `.class` files are generated by `javac`; they can be regenerated at any
time from the source file.

## Limitations

This is intentionally a single-user local demonstration. It is not suitable
for real financial use because it has no multi-user access control, audit
service, encrypted database, network security, regulatory controls, or
integration with a payment processor.

For a production-grade system, use a real database, a dedicated identity
provider, managed secret storage, server-side authorization, immutable audit
logging, encrypted backups, monitoring, and professional security review.
